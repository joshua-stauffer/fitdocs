**Hard rules for every task**

- **Absent is `None`.** No catalog code substitutes zero, an empty string, a
  default or an interpolated value for an absent value; zero is drawn as
  zero; a missing row is drawn as nothing.
- **Pure.** No clock, randomness, generated ids, environment reads, file or
  network access in `src/`. Goldens are written only by a test module's
  `main()` writer, never during a pytest run.
- **Imports.** Catalog modules import only the standard library,
  `fitdocs.render.charts.{svg,series,palette}`, `fitdocs.units` and lower
  kit ranks in the order `units → data → problems → schema → format → ticks
  → theme → layout → scales → cells → frame → marks → cartesian → validate
  → kinds/* → registry → api → __init__`. A kind never imports another
  kind, `registry` or `api`.
- **Core and existing charts untouched.** At every task this command prints
  nothing:

- **Shared test helpers are read-only** (chart-kit tasks.md § Shared source
  files): no task edits `tests/render/charts/kit/_helpers.py` or
  `goldens.py`; a missing helper is a stop-and-report.
- **Golden discipline** (chart-kit tasks.md Hard rules § Golden discipline,
  and its task 6.2's class rule). Goldens are compared as bytes, never
  created by a test run, and regenerated only by the owning module's
  `main()` (`uv run python -m tests.render.charts.kit.test_<kind>`). Every
  golden is shown able to fail by at least one named mutation of production
  code, recorded with the golden(s) it reddened: kind-local mutations in
  the kind's own task (group 2); the standard classes, and the grid classes
  reached by `cells`, in task 3.2 alone. A golden whose fixture cannot be
  made to fail is reported, not kept. Each kind's `CASES` lists `typical`
  first (chart-kit's registry round trip renders the first entry).
- **Mutations run through `uv run pytest` only** (`change-protocol.md` §
  Fixture Discrimination): applied, observed red, reverted, observed green,
  recorded. Revert by restoring a `cp` of the file taken before the
  mutation, never `git checkout -- <path>`, `git stash` or
  `git reset --hard`. A listed mutation that cannot be made red is reported
  UNPINNED, never hidden by weakening an assertion. Before submitting, run
  the prose-claim grep of `change-protocol.md` over the changed test files,
  and read every factual sentence in them, re-running or deleting each
  claim.
- **A `(P)` task never mutates a module outside its own boundary**, and runs
  its mutation passes over its own test files only. Kind tasks (group 2)
  mutate only their own kind module. Mutations of `cells`, `frame`,
  `layout`, `scales`, `format` or `cartesian` that reach several kinds'
  goldens run once, sequentially, in task 3.2 (and 3.3 for budgets).
- **Fixtures discriminate.** Category first appearance differs from
  alphabetical order; rows are not pre-sorted by x or date; numbers on a band
  axis arrive out of order; values are pairwise distinct where a mapping is
  asserted; offending rows sit at indices other than 0; an asserted end state
  is shown false beforehand.
- **Shell safety.** Never `rm -rf`, `git init`, `git reset --hard`,
  `git clean` or `git checkout -- <path>`; never chain a destructive command
  after `cd`.
- **Types and lint.** Each task runs `uv run mypy` (config-driven), and
  `uv run ruff check` and `uv run ruff format --check` on its changed files.
- **Stop and report** on any need for: a runtime dependency; an edit to a
  core kind module, a core golden, a shared test helper or the four
  renderers; a change to an existing shared-layer signature or behaviour; a
  shared-layer change from a kind task; an edit to another spec's files; a
  failed upstream check (items 1–7).
