# Implementation Plan

## Upstream Prerequisites

Everything this plan touches already exists on `main`; no sibling spec must
land first. The contracts it extends, and must not re-specify:

- **`wiki-contract`** — `src/fitdocs/contract.py` (the pure policy leaf; its
  `__all__` is pinned exactly by `tests/test_public_api.py`), `MANAGED_KEYS`
  and the AST anti-drift test that holds it equal to what the frontmatter
  builder emits, `unmanaged_keys`, `FindingKind`/`audit`, the fragment-composed
  `AGENTS.md` declaration and its byte-goldens, `docs/ownership-contract.md`
  and its conformance test, `CONTRACT_VERSION`.
- **`workout-docs`** — `DocContext` (a frozen dataclass with one defaulted
  field already) and `build_frontmatter` (one `yaml.safe_dump`; the only module
  allowed to name `yaml`, and only for `safe_dump`).
- **`training-load`** — the load pass's line-level frontmatter editor, which
  this plan changes in no way and only proves.

**Hard rule for every task**: `MANAGED_KEYS` is not edited, `DOC_VERSION` is
not raised, and no new module, command, dependency or owned path appears. A
task that finds it needs one of those stops and reports rather than widening.

## Implementation Notes

- 1.1: pin a dataclass annotation with `typing.get_type_hints()` + `typing.get_args()`,
  never by reading back a value the test itself passed to the constructor. The raw
  `__annotations__` entry here is the *string* `'float | None'` (the module uses
  `from __future__ import annotations`), so `get_args` on it returns `()` and the
  assertion reds rather than silently passing -- it is fail-safe in the right
  direction. `hasattr` on a dataclass field is `False` either way and pins nothing.
